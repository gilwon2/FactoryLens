# FactoryLens

제조 생산·검사 CSV를 업로드하면 데이터를 검증한 뒤 **공정별·제품별 생산량, 불량 수량, 불량률과 불량 유형별 비중**을 보여 주는 Streamlit 웹 애플리케이션입니다.

> ⚠️ 이 저장소의 모든 데이터는 `scripts/generate_sample_data.py`로 생성한 **가상 데이터**이며 실제 공장 데이터가 아닙니다.

- 배포 주소: _(배포 후 추가)_
- 문서: [ERD](docs/ERD.md) · [지표 정의](docs/metrics.md) · [테스트 결과](docs/test_report.md) · [오류 예시 CSV](data/invalid_examples/README.md)

## 주요 기능

| 기능 | 내용 |
|---|---|
| CSV 업로드·검증 | 필수 컬럼, 데이터 타입, 결측, 중복, 파일 간 정합성을 검사합니다. 정상 행만 적재하고, 제외한 행은 줄 번호와 사유를 표로 보여 줍니다. |
| SQLite 적재·SQL 집계 | 세션마다 인메모리 SQLite에 적재하고 SQL로 집계합니다. |
| 핵심 지표 | 생산량, 불량 수량, 불량률(가중 평균), LOT 수 |
| 분석 탭 | 공정별, 제품별, 불량 유형별(비중), 일자별 추이 |
| 필터 | 생산일 범위, 공정·제품 다중 선택 |
| 결과 다운로드 | 탭별 CSV. 엑셀에서 한글이 깨지지 않게 저장하고(UTF-8 BOM), 수식 주입을 방지합니다. |
| 체험 | "샘플 데이터로 체험" 버튼과 샘플 CSV 다운로드 |

## 빠른 시작

Python 3.10 이상이 필요합니다.

```bash
git clone <저장소 주소>
cd FactoryLens
python -m venv .venv
.venv\Scripts\activate            # macOS/Linux: source .venv/bin/activate
pip install -r requirements.txt
streamlit run app.py              # http://localhost:8501
```

테스트를 실행하는 방법입니다.

```bash
pip install -r requirements-dev.txt
python -m pytest -q
```

샘플 데이터와 오류 예시를 다시 만드는 방법입니다. 시드가 고정되어 있어 항상 같은 결과가 나옵니다.

```bash
python scripts/generate_sample_data.py
python scripts/make_invalid_examples.py
```

## 입력 데이터 형식

**production.csv** (LOT당 1행, 필수 업로드)

| 컬럼 | 규칙 |
|---|---|
| `lot_id` | 필수, 파일 내 고유 |
| `work_date` | `YYYY-MM-DD`, 실제 존재하는 날짜 |
| `process` | 필수 (예: PRESS, WELD, PAINT, ASSY) |
| `product` | 필수 |
| `produced_qty` | 0 이상의 정수 |

**defects.csv** (LOT×불량 유형당 1행, 선택 업로드)

| 컬럼 | 규칙 |
|---|---|
| `lot_id` | production에 있는 LOT |
| `defect_type` | 필수, `lot_id`와 함께 파일 내 고유 |
| `defect_qty` | 0 이상의 정수 |

- 컬럼명의 대소문자와 앞뒤 공백은 무시합니다. 추가 컬럼은 안내 후 무시합니다.
- 인코딩은 UTF-8, UTF-8 BOM(엑셀 "CSV UTF-8"), CP949를 지원합니다.
- defects.csv를 올리지 않거나 헤더만 있으면 모든 LOT의 불량을 0으로 계산합니다.

## 데이터 검증 규칙

| 단계 | 규칙 | 처리 |
|---|---|---|
| F 파일 | 빈 파일, 읽을 수 없는 인코딩, 열 개수가 다른 줄, 필수 컬럼 누락, production에 데이터 행 없음 | **파일 거부** |
| D 중복 | 모든 값이 같은 완전중복 | 첫 행만 반영하고 경고 |
| D 중복 | 키(`lot_id` / `lot_id`+`defect_type`)는 같은데 값이 다름 | 그 키의 행 **전부 제외** |
| R 행 | 결측, 정수가 아닌 수량·음수, 잘못된 날짜 | 행 제외 |
| X 교차 | production에 없는 LOT의 불량 행 | 불량 행 제외 |
| X 교차 | LOT의 불량 합계가 생산량보다 많음 | 해당 LOT의 생산·불량 **모두 제외** |
| Z 0건 | 검증 후 유효한 생산 데이터가 0건 | 적재 중단 (오류 목록은 표시) |

일부 행이 제외되면 화면에 "지표는 적재된 데이터만으로 계산한 값"이라는 경고가 항상 표시됩니다.

## 지표 정의

- **불량률(%)** = 불량 수량 ÷ 생산량 × 100 (소수 둘째 자리)
  - 생산량이 0이면 계산하지 않고 `-`로 표시합니다.
  - 그룹 불량률은 LOT별 불량률의 단순 평균이 아니라 **합계 ÷ 합계(가중 평균)**입니다.
- **불량 수량**은 불량품 개수입니다. 불량이 발생한 LOT 수가 아닙니다.
- 자세한 집계 기준과 SQL은 [docs/metrics.md](docs/metrics.md)에 있습니다.

## 설계 결정

| 문제 | 결정 | 이유 |
|---|---|---|
| 불량 유형이 여러 개인 LOT를 어떻게 저장할지 | 생산·불량 CSV와 테이블을 1:N으로 분리 | 한 테이블에 두면 생산량이 행마다 반복되어 중복 합산될 위험이 있습니다. |
| 같은 키의 값이 서로 다른 행 | 어느 쪽도 채택하지 않고 모두 제외 | 어느 값이 맞는지 시스템이 판단할 근거가 없습니다. 완전중복은 같은 데이터가 두 번 들어온 것으로 보고 1행만 반영합니다. |
| 중복과 타입 오류를 검사하는 순서 | 중복을 먼저 검사 | 타입 오류 행이 먼저 빠지면 같은 키의 다른 행이 충돌 없이 통과해 버립니다. |
| 오류 행이 있는 파일 | 정상 행만 적재하고 제외 내역을 표시 | 사용자가 데이터를 고치지 않아도 분석할 수 있게 하되, 제외 사실은 숨기지 않습니다. |
| 생산·불량 JOIN 시 생산량 중복 | 불량을 LOT별로 먼저 합산한 뒤 LEFT JOIN | JOIN 팬아웃을 막고, 불량이 없는 LOT도 집계에 포함합니다. |
| 데이터 저장 위치 | 세션별 인메모리 SQLite, 업로드마다 교체 | 공개 배포 환경에서 사용자 간 데이터가 섞이지 않고 서버에 남지 않습니다. |

## 프로젝트 구조

```
FactoryLens/
├─ app.py                       # Streamlit 화면 (업로드 → 리포트 → 필터 → 지표·탭·다운로드)
├─ factorylens/
│  ├─ validation.py             # CSV 읽기와 검증 (F·D·R·X·Z 규칙)
│  ├─ db.py                     # SQLite 스키마와 적재
│  ├─ metrics.py                # 집계 SQL과 불량률
│  └─ export.py                 # 다운로드 CSV (BOM, 수식 주입 방지)
├─ scripts/                     # 샘플 데이터·오류 예시 생성
├─ data/sample/                 # 가상 샘플 데이터
├─ data/invalid_examples/       # 오류 처리 시연용 CSV
├─ tests/                       # pytest (126개)
└─ docs/                        # ERD, 지표 정의, 테스트 결과
```

화면(`app.py`)과 로직(`factorylens/`)을 분리해서 로직은 Streamlit 없이 pytest로 테스트합니다.

## 가정과 한계

- **전수검사 가정:** 검사 수량과 생산 수량을 같게 봅니다.
- **대표 불량 유형:** 불량품 1개에 대표 불량 유형 1개만 기록한다고 가정합니다.
- **누적 저장 없음:** 업로드한 데이터는 세션 동안만 메모리에 있고 저장·누적되지 않습니다. 새로고침하거나 다시 업로드하면 사라집니다.
- **코드값 대소문자:** 공정·제품 코드는 대소문자를 구분합니다(`PRESS` ≠ `Press`).
- **업로드 크기:** 최대 10MB입니다. 20만 행 기준 검증에 약 2초가 걸립니다.
